# DECISIONS.md — いま有効な設計判断

`DESIGN.md` は設計判断を時系列に追記する履歴で、後の判断が前の判断を覆す。この文書は、そのうち**いま有効な判断だけ**を領域ごとに並べた索引である。各項目は要点だけを書き、理由・退けた案・既知の限界は D 番号の先(`DESIGN.md`)を読む。

- 正典は `DESIGN.md`。食い違ったら `DESIGN.md` が正しく、この文書を直す
- 新しい判断を `DESIGN.md` に足したら、この文書の該当する領域に 1 項目を足す(要約を `CLAUDE.md`・`docs/DEVELOPMENT.md` に写さない)
- 判断を覆したら、覆された側の `DESIGN.md` の見出しの末尾に `〔D-xxx で覆した〕`(一部なら `〔一部を D-xxx で覆した〕`)を付け、末尾の「覆された判断」の表に行を足す。すべて覆された判断は領域の一覧から外す
- 上の約束は `tests/guards/design-decisions.test.ts` が検査する(すべての D 番号がこの文書のどこかに載っていること、見出しの印と表が一致すること、リンク先の D 番号が実在すること)

## 全体の方針と構成

- [D-052](../DESIGN.md#d-052): 定義と値の正は OscDesk(サーバー)が持ち、Unity は受けてエコーを返す。案件差分はコードでなくデータ(config・サーフェス定義)で表す
- [D-025](../DESIGN.md#d-025)・[D-024](../DESIGN.md#d-024): Node のブリッジ(OSC と WebSocket)と NiceGUI の UI(Python)の 2 プロセス構成。UI は NiceGUI を主線とする
- [D-026](../DESIGN.md#d-026)・[D-027](../DESIGN.md#d-027): 機械名 `oscdesk`、表示名 `OscDesk`。Unity との契約 `/sys/*` は据え置き、内部・UI 向けは `/oscdesk/*`
- [D-122](../DESIGN.md#d-122)・[D-123](../DESIGN.md#d-123)・[D-124](../DESIGN.md#d-124)・[D-126](../DESIGN.md#d-126): 判定・編集の規則・部品の木の組み立てはブリッジが持ち、UI は描くだけ。操作中の保護・間引き・下書き・まとめ送りの組み立ては UI に残す
- [D-134](../DESIGN.md#d-134): ブリッジの `src` は `domain/`(I/O を持たない規則と状態)・`adapters/`(ソケット・ファイル・OS)・`app/`(起動と配線)の 3 層で、依存は app → adapters → domain の向きだけ(`tests/guards/bridge-layers.test.ts` が守る)
- [D-005](../DESIGN.md#d-005): リポジトリに Unity プロジェクト `OscSurface/` が同居する。Node 側に `Library/` という名前のディレクトリを作らない

## UI ↔ ブリッジのプロトコル

- [D-028](../DESIGN.md#d-028): WebSocket は `v` と `type` を持つエンベロープ付き JSON。OSC 引数は型タグ付き、blob は base64
- [D-110](../DESIGN.md#d-110): 共通のフレームはパラメータ ID と JSON の値で書き、OSC の語は `osc.*` のフレームだけに置く。ブリッジの中に通信アダプタの境目(`target-adapter.ts`)を 1 つ置き、`hello.adapters` で知らせる
- [D-029](../DESIGN.md#d-029): 設定は `unity` / `bridge` / `ui` の 3 ブロック。起動時の実効値を READY 行と `hello` で配り、UI は設定ファイルを読まない(ネットワークの 3 項目は [D-113](../DESIGN.md#d-113) で実行中に変えられる)
- [D-023](../DESIGN.md#d-023)・[D-071](../DESIGN.md#d-071): UI の WebSocket は `proxy=None` で接続し、受信上限を 16 MiB にする
- [D-129](../DESIGN.md#d-129): 上りのフレーム・UDP の受信・HTTP の想定外の例外はその 1 件だけ捨てて記録し、ブリッジは止めない
- [D-116](../DESIGN.md#d-116): 送った結果が届いたかをブリッジが受信の種類と突き合わせて `delivery` で配り、UI は送り先ブロックの点灯で示す

## サーフェス定義

- [D-043](../DESIGN.md#d-043)・[D-117](../DESIGN.md#d-117): 定義はパラメータ層 + 画面層の JSON(版 2)で、本体と OSC の結び付け `bindings.osc` に分ける。正典は zod(`packages/shared`)、JSON Schema は生成物。版 1 は読み込み時に版 2 へ移す
- [D-044](../DESIGN.md#d-044): 定義はブリッジが名前付きで保管・配信し、上書きのたびにバックアップを残す。不正な定義は採用せず要求元へ `notice`
- [D-103](../DESIGN.md#d-103)・[D-121](../DESIGN.md#d-121): 型・制約(Range など)・表示ヒントは別の軸。拡張パッケージの型は基本型・Record・配列の組み合わせで、フラットな Record を 1 アドレスの引数の並びで送る(入れ子・可変長は CBOR に先送り)
- [D-050](../DESIGN.md#d-050)・[D-061](../DESIGN.md#d-061): 複数の OSC のまとめ送りは定義の `actions` で表す。送り先の展開はブリッジが部品の木で行い([D-124](../DESIGN.md#d-124))、UI は値を集めて 1 個の `batch` を組み立てて送り、エコーで確認する。レコードには `scope`(`row` / `all`)と `record` step を使う
- [D-053](../DESIGN.md#d-053)・[D-054](../DESIGN.md#d-054)・[D-055](../DESIGN.md#d-055): Unity が実行時に持つ文字列の一覧は、定義が宣言したアドレス(`optionsFrom`)へ届く値として受け、全台の和集合をブリッジが組み立てて `runtimeOptions` で配る。一覧・要求のアドレスは値のアドレスと重ねない
- [D-077](../DESIGN.md#d-077): 要求を持つ一覧の近くに「Sync」を置き、その一覧の要求だけを全宛先へ送る
- [D-088](../DESIGN.md#d-088): Unity から届いた一覧は「届いた一覧」として持ち、初報だけ自動で反映し、その後の変化は UI の「反映」で取り込む
- [D-017](../DESIGN.md#d-017): bool はワイヤでは `i` の 0/1

## レコード(可変個の行)

- [D-059](../DESIGN.md#d-059)・[D-061](../DESIGN.md#d-061): 個数が実行時に変わる対象は、先頭のキー(`s`)とフィールドの列を 1 アドレスで運ぶレコードで表し、キーの一覧は `keysFrom` で受ける
- [D-062](../DESIGN.md#d-062): ブリッジはレコードの保持値をキーごとの行で持ち、一覧から消えたキーの行も残して再送する(行を作る時機は [D-088](../DESIGN.md#d-088))
- [D-075](../DESIGN.md#d-075)・[D-087](../DESIGN.md#d-087): 行は通常の画面から追加・削除でき、`keysFrom.source: "ui"` の一覧は OscDesk が持つ。UI で管理する行は変わらない ID で指し、Name は別のラベル
- [D-064](../DESIGN.md#d-064)・[D-072](../DESIGN.md#d-072): UI はレコードを行 = キーの表で描き、行の増減では画面を作り直さない。欄はカードで包まず dense の 1 段
- [D-066](../DESIGN.md#d-066)・[D-073](../DESIGN.md#d-073)・[D-074](../DESIGN.md#d-074)・[D-076](../DESIGN.md#d-076): 列の一括操作(ボタン・一括トグル)は見出しの直下、表全体のアクションは表の右の縦長ボタン。キーの列は広く、スイッチの列は固定の狭い幅
- [D-069](../DESIGN.md#d-069): アクションのボタンには定義のラベルだけを出す

## 値の保持と再送

- [D-045](../DESIGN.md#d-045): 狙いの値(`state`)はブリッジが保持し、Unity の初回到達・回復・採用で再送する。エコーは届いた確認で保持値を書き換えない。`trigger` は保持も再送もしない
- [D-058](../DESIGN.md#d-058): 保持値は定義名ごとのファイルへ間引いて原子的に保存し、ブリッジ起動後最初の採用でだけ復元する
- [D-115](../DESIGN.md#d-115): 生成担当の命令で生成したものは PC ごとに記録し、起動の合図と「記録に合わせる」で生成し直す(`trigger` を再送しない規則の例外)
- [D-090](../DESIGN.md#d-090): 定義・保持値・OSC パッドをプロジェクトファイル 1 つで書き出し・取り込みする。取り込んだ値は全宛先への再送まで Unity へ送らず、自動の再送も止める
- [D-067](../DESIGN.md#d-067): 送った OSC はブリッジが直近 1,000 件を記録して UI へ配る(揮発する表示用)。通知の履歴は UI のページごと

## 宛先とネットワーク

- [D-046](../DESIGN.md#d-046): 複数の Unity を同時に動かし、操作は全宛先へ送り、再送は宛先を絞れる。死活監視は宛先ごとの ping/pong
- [D-078](../DESIGN.md#d-078): 送り先は UI から実行中に選び直せ、選択はブリッジがファイルへ保存して設定ファイルの宛先より優先する。LAN の走査はブリッジが UDP の掃引 + ARP 表で行う
- [D-079](../DESIGN.md#d-079)・[D-085](../DESIGN.md#d-085)・[D-093](../DESIGN.md#d-093): 「全てのデバイス」はネットワークのブロードキャストへ送り、pong を返したホストごとに到達を数えてユニキャストで再送する。到達はホストを含む最も狭い走査ネットワークで判定する
- [D-086](../DESIGN.md#d-086)・[D-089](../DESIGN.md#d-089)・[D-091](../DESIGN.md#d-091): 送信先パネルは画面の右側(狭い画面では本体の上)で、Inspector と共用する。検索は正規表現。親を選ぶと子にもチェックが付く
- [D-092](../DESIGN.md#d-092): 端末の別名は UI から付け、ブリッジが MAC(無ければ host)をキーに保存する
- [D-094](../DESIGN.md#d-094): 宛先ごとの再送は「再送」タブに置き、ブリッジの PC は「サーバー PC」と書く
- [D-113](../DESIGN.md#d-113): ターゲット向けのネットワーク・ターゲットの範囲・接続してよいブラウザの範囲は実行中に変えられる。localhost は常に許可

## セキュリティ

- [D-082](../DESIGN.md#d-082)・[D-083](../DESIGN.md#d-083): ブリッジの WebSocket は Origin 付き(ブラウザ発)のハンドシェイクを拒否し、HTTP は Origin 付きの状態を変えるリクエストを拒否する。認証は提供しない(信頼できる LAN 内だけで使う)

## UI(NiceGUI)

- [D-021](../DESIGN.md#d-021): 表示はページ側の 20Hz タイマーで状態を取り込み、バックグラウンドから UI 要素を触らない
- [D-047](../DESIGN.md#d-047): UI はサーフェス定義と保持値で駆動し、Unity のマニフェストを読まない
- [D-048](../DESIGN.md#d-048): 画面層は `layout.py` が描き、行の幅は 12 分割の比で分けて狭い画面で折り返す
- [D-049](../DESIGN.md#d-049): 定義の編集は作業コピー方式で、競合は検知して警告し、上書きは確認つき(編集の規則は [D-123](../DESIGN.md#d-123) でブリッジ)
- [D-033](../DESIGN.md#d-033): input の編集中の保護はフォーカスで始め、フォーカス中は同期タイマーで延長する
- [D-056](../DESIGN.md#d-056): 一覧の候補の差し替えでは値を送らず画面も作り直さない。一覧に無い現在値は印を付けて残す
- [D-111](../DESIGN.md#d-111): 操作中のロックは部品と Record の行の単位で 2 秒の貸し出し。ロック中の単位を含むまとめ送りは全体を断る
- [D-125](../DESIGN.md#d-125)・[D-128](../DESIGN.md#d-128): 部品の木の部品は 1 件にまとめて添字で指し、木の大きさに上限を置く。アクションの上限超は `truncated: true` で示す
- [D-118](../DESIGN.md#d-118): 設計図が送り元と一致しない PC は、送り先ブロックの赤い枠と印で示す

## OSC パッド

- [D-080](../DESIGN.md#d-080): OSC パッドはサーフェス定義と別の文書としてブリッジが保管・採用し、押下はボタンの id で送る。保持値・再送に載せない
- [D-081](../DESIGN.md#d-081)・[D-084](../DESIGN.md#d-084): 実行モードは pointerdown で送り、編集モードは作業コピーを Inspector で編集する。格子の大きさは Inspector の外で、位置の編集は設定のコピーで行う

## 設計図(Catalog)と Sync

- [D-101](../DESIGN.md#d-101): ターゲットは UI の設計図を Sync でサーバーへ送る。設計図は PC ごとに取得元付きで保持するテンプレートで、照合・誤接続ガードは作らない
- [D-104](../DESIGN.md#d-104)・[D-131](../DESIGN.md#d-131): 設計図は `/sys/catalog/*` で受け、`catalog` フレームで変わった PC だけを配る。上限は PC ごと
- [D-112](../DESIGN.md#d-112): 設計図からの既定の画面はブリッジが作り、保存した画面を優先する。設計図は再起動をまたいで保存しない
- [D-114](../DESIGN.md#d-114)・[D-120](../DESIGN.md#d-120): Unity の受け口が Registry に沿って設計図を送り、全体の送り直しは間隔とバイト数の予算で絞る

## Unity 側の受け口(`com.hidano.oscdesk`)

- [D-051](../DESIGN.md#d-051): Unity からマニフェスト(構造の申告)を受ける経路は持たない(設計図の Sync は [D-101](../DESIGN.md#d-101))
- [D-095](../DESIGN.md#d-095)・[D-096](../DESIGN.md#d-096): 受け口は OSC 1.0 のコーデックと UDP を自前で持ち(特定の OSC ライブラリに依存しない)、UPM パッケージとして `OscSurface/Packages/` に埋め込む
- [D-057](../DESIGN.md#d-057)・[D-098](../DESIGN.md#d-098): 一覧は `SendStrings` で返し、名前の一覧の正規化と変わったときだけ送る部品を持つ
- [D-060](../DESIGN.md#d-060): 受信の観測(最終受信時刻と途絶・再開)を公開するが、受けて返すだけの振る舞いは変えない
- [D-063](../DESIGN.md#d-063)・[D-099](../DESIGN.md#d-099): レコードは `OscRecord` 1 個で UnityEvent に渡し、帳簿は値の型を型パラメータにした型で中核に置く。名前空間は `OscDesk.Receiver`
- [D-097](../DESIGN.md#d-097): トリガ待ちのアプリ向けに、再送を自動で適用する窓 `OscResendWindow` を持つ
- [D-100](../DESIGN.md#d-100): `[OscAddress]` の宣言からエディタが行のリスナーを登録する
- [D-102](../DESIGN.md#d-102)・[D-105](../DESIGN.md#d-105): 行の無いアドレスは既定で警告しない。処理しなかった受信は `/sys/ignored`・`/sys/failed` で任意に知らせる
- [D-106](../DESIGN.md#d-106)・[D-130](../DESIGN.md#d-130): 振り分けは OSC 1.0 のアドレスパターンを解釈し、1 パターン・1 データグラム・1 フレームの処理量に上限を置く
- [D-107](../DESIGN.md#d-107)・[D-108](../DESIGN.md#d-108)・[D-109](../DESIGN.md#d-109): 受け手は基底 `OscTarget` を継承して Registry に登録し、振り分けは Registry で行う。同じシーンで重なった対象名はエディタが付け直す

## 起動・ログ・ツール

- [D-004](../DESIGN.md#d-004): pnpm は corepack 経由で使う
