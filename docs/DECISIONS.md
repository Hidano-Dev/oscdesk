# いま有効な設計判断

`DESIGN.md` は設計判断を時系列に積んだ記録で、後の判断が前の判断を覆している。この文書は、そのうち **いま効いている判断だけ** を領域ごとに並べたもの。各項目の末尾の D 番号は `DESIGN.md` の見出し(`### D-xxx:`)で、理由・退けた案・既知の限界はそちらにある。「覆した」は、その項目が置き換えた過去の判断を示す。

- 判断を足したり覆したりしたら、`DESIGN.md` に追記したうえでこの文書を書き換える。覆された `DESIGN.md` の項目には見出しに印(`(→ D-xxx で覆した)` / `(一部 → D-xxx)`)を足す
- `tests/guards/decisions.test.ts` が、この文書と印の D 番号が `DESIGN.md` にあること、`DESIGN.md` のどの項目も「この文書の項目の行末の D 番号に載る」か「全体を覆した印を持つ」かのどちらかであることを検査する(説明文の中の参照は数えない)
- 前提: 本システムは認証を提供しない。信頼できる LAN 内での利用が前提で、インターネットや信頼できないネットワークへ公開してはならない。以下の上限や許可リストはこの前提の上での守りで、認証の代わりではない

## アーキテクチャと責務境界

- **ブリッジ 1 プロセスと SPA**: Node.js のブリッジが Unity との OSC/UDP と UI との WebSocket を集約し、UI(表示と操作)はブリッジが配る SPA がブラウザの中で担う。動かすプロセスはブリッジ 1 つ。NiceGUI 版の UI と Python の経路(`.venv`・pytest)、旧基盤の外部 UI とそれに依存した動的生成・診断パネル・ブラウザ検査の E2E は撤去した。`corepack pnpm test` は Node だけで動く。(D-162・D-025・D-024。覆した: D-001〜D-003・D-007〜D-011・D-021・D-023・D-071)
- **UI の方式**: UI はブリッジが静的ファイルとして配る TypeScript の SPA(Preact + @preact/signals、esbuild、型とスキーマは `@oscdesk/shared` をそのまま使う)。NiceGUI 版からパネル単位で移し終えた。ブリッジと UI の責務の分離は変えない(SPA は WebSocket のプロトコルだけを使う)。(D-137・D-162)
- **作り直し(方針。HID-483 で移行中)**: 画面を作る仕組みを OSC パッド 1 つにまとめ、サーフェス定義・編集モード・部品の木を撤去する。ターゲットとの連携は OSCQuery(mDNS の `_oscjson._tcp` と HTTP の名前空間)に合わせ、独自の設計図と LAN の走査を撤去する。ターゲットの起動は `HOST_INFO` と `/sys/pong` に載る起動 ID の変化で知る。選択肢の一覧と Unity が持つ行は OSCQuery で受け、UI で管理する行と表はパッドの部品に残す。自動再送はトグルで既定 OFF、部品ごとに送り直さない設定と任意の PC への手動の同期を持つ。生成の記録は撤去し、作り直しは受信側の責務にする。実装が済むまでは、この文書のほかの項目(いまの動き)が効く。(D-163・D-164・D-165・D-166)
- **SPA の配り方と部品**: SPA は `packages/web-ui`。ブリッジが既定の設定(`webUi.enabled`)で HTTP の `/` に決まった名前のファイルだけを配り、gzip・`ETag`・埋め込みの拒否を付ける。READY 行の `webUiPath` でランチャーが URL を出す。どのパネルも共有の接続 `bridge-link`(下りも上りも shared のスキーマで検証、heartbeat、つなぎ直し)・通知・`Check` を使い、パネルは logic / store / panel の 3 ファイルに分ける。(D-138)
- **名称と名前空間**: 機械名は `oscdesk`、表示名は `OscDesk`。Unity との契約は `/sys/*`、内部と UI 向けは `/oscdesk/*`。(D-026・D-027)
- **定義と値の正はサーバー(ブリッジ)**: 操作対象の定義と狙いの値は OscDesk が持つ。Unity は受けてエコーを返し、加えて UI の設計図を Sync で送る(設計図は PC ごとに取得元付きで持つテンプレートで、ターゲットとの紐づけ・照合・誤接続ガードは作らない)。Unity からマニフェストを受ける経路は撤去したまま戻さない。(D-052・D-101・D-051。覆した: D-051 の「構造を申告しない」の方針、D-052 の Unity との契約の一部)
- **判定の正は 1 か所(UI は描くだけ)**: 定義・パッド・プロジェクトファイルの検証、定義とパッドの編集の規則、表示する部品の木の組み立てはブリッジ(`packages/shared` と `packages/bridge`)だけが持ち、UI は写しを持たない。UI に残すのは操作の手触りに関わる値の扱い(操作中の保護・送信の間引き・下書き)と、まとめ送りの組み立て。(D-122・D-123・D-124・D-126)
- **通信アダプタの境目**: UI ↔ サーバーの共通のフレームはパラメータ ID と型タグの無い JSON の値で書き、OSC 専用の機能(生の OSC・`osc.batch`・送信ログ・OSC パッド)は `osc.*` に置く。ブリッジの中の境目は `target-adapter.ts` の 1 つで、実装は OSC だけ。`hello.adapters` に `osc` があるときだけ UI は OSC 専用の機能を出す。共通のフレームに OSC の語が混ざると `tests/guards/osc-vocabulary.test.ts` が落ちる。(D-110・D-117)
- **ブリッジの 3 層**: `packages/bridge/src` は `domain/`(I/O を持たない規則と状態。外の世界にはポート経由でだけ触る)・`adapters/`(ソケット・ファイル・OS)・`app/`(起動と配線)に分け、依存は app → adapters → domain の向きだけ。`tests/guards/bridge-layers.test.ts` が守る。`surface-core` は `domain/surface-core/` の責務ごとのファイル。ほかの TS パッケージは平置きのまま。(D-134)
- **OSC ネイティブ UI の中継**: TouchOSC などの OSC ネイティブ UI は、評価用にブラウザの UI(SPA)と併存できる(設定の `oscUi.enabled`、`launchers\start-oscdesk-touchosc.bat`、`docs/TOUCHOSC_EVAL.md`)。ブリッジがその端末の OSC を Unity へ中継し、主系のエコーを端末へ返す。中継した値は UI の操作と同じく保持値を書き換える(送信ログの契機は `relay`)。Unity の宛先と同じホストからの OSC はエコーとみなして中継しないので、端末は Unity と別のホストに置く。中継はロックを見ない。(D-024・D-045・D-046・D-058・D-067・D-079・D-111)

## Unity との契約(受け口)

- **基本の契約**: OSC 1.0 の標準の型だけで成り立たせる(特定の Unity の OSC ライブラリに依存しない)。`/sys/ping` → `/sys/pong`、受けたアドレスへのエコー(行の有無・型の適否にかかわらず返す)、bundle は展開して順に処理、bool は `i` の 0/1。UDP の順序の入れ替わり・遅れは LAN 前提の既知の制限。(D-052・D-017・D-042)
- **`/sys/stats`(任意)**: `/sys/stats/request` に `/sys/stats`(`received` / `parseErrors` / `lastReceivedAt` の JSON)を返してよい。手動の実装確認用で、ブリッジは送らず、受け取っても使わない。返さなくても契約違反ではない(`docs/UNITY_PROTOCOL.md` §1、受け口は `OscLink`)。診断パネルでの観測は撤去した。(D-018・D-031・D-051・D-108)
- **設計図の Sync**: ターゲットは `/sys/catalog/*`(`begin` / `add` / `remove` / `end`、`request`、差分の後の `digest`)で 1 項目 1 メッセージの設計図を送る。PC は送信元ホストで区別し、照合は設計図全体の CRC32。項目数・大きさに上限があり、1 PC 8 MiB・保持量 64 MiB まで。受け口は待ち受けの開始と Sync の要求で全体を、変化はフレームごとに差分で送り、全体の送り直しは 1 秒と送信量の予算で絞る。(D-104・D-131・D-114・D-120)
- **任意の受信の報告**: 受け口は処理しなかった受信を `/sys/ignored`(行の無いアドレス)・`/sys/failed`(型・Record の不一致、例外)でエコーの後に知らせてよい(任意の契約。件数と文字数に上限)。(D-105)
- **実行時の一覧の応答**: `optionsFrom` / `keysFrom` の一覧は、定義が宣言した通常のアドレスへ `s` を並べた 1 メッセージで返す(`/sys/*` は使わない)。要求は既存の Trigger の行で受ける。名前の正規化と変化時だけ送る部品(`OscNameList` / `OscNameListPublisher`)を受け口が持つ。(D-053・D-057・D-098)
- **受け口のパッケージ**: UPM パッケージ `com.hidano.oscdesk`(本体は別リポジトリ `Hidano-Dev/oscdesk-unity` の `Packages/com.hidano.oscdesk/`、中核 `Runtime/Core/` は `UnityEngine` 非依存)。SemVer で、契約の Unity 側の振る舞いを変える変更は major。npmjs への公開は所有者の手動。git の URL は `https://github.com/Hidano-Dev/oscdesk-unity.git?path=Packages/com.hidano.oscdesk`。(D-096・D-136)
- **契約と見本の正**: Unity との契約 `docs/UNITY_PROTOCOL.md` と言語間の見本(`protocol/osc-binary-samples.json`・`protocol/catalog-samples.json`)の正は本リポジトリ。`oscdesk-unity` はパッケージに写しを持ち、その CI が写しを本リポジトリの `main` と比べる。見本を変えたら `oscdesk-unity` で写し直す。(D-136)
- **自前のコーデックとトランスポート**: 受け口は外部の OSC ライブラリを使わず、OSC 1.0 のコーデックと IPv4 の UDP ソケット 1 本(受信と送信を兼ねる。`SIO_UDP_CONNRESET` を切る)を持つ。言語間のバイト列の見本は `protocol/osc-binary-samples.json`。(D-095。覆した: D-015)
- **振り分けの仕組み**: 受け手は基底 `OscTarget` を継承して有効化で `OscRegistry` に登録し、実行中の重複は後からの登録を受け付けない。生成担当 `OscSpawner` は命令で渡された名前を対象名にする。`OscReceiver` はシリアライズ値と公開 API を保ったまま、受信・Link・Router を中核に分け、対応表の行をアドレスごとに Registry へ載せる。シーンの中で重なった対象名はエディタが保存時と Play の開始時に付け直す。(D-107・D-108・D-109)
- **アドレスのパターンと処理量の上限**: 振り分けは OSC 1.0 のパターン(`?` `*` `[]` `{}`)を解釈し、1 通・1 フレームの呼び出し数と判定量に上限を置く。1 データグラムは 1024 メッセージ、1 フレームは 4096 メッセージまで(bundle は丸ごと捨てるか丸ごと遅らせる)。(D-106・D-130)
- **ログの出し分け**: 行の無いアドレスの警告は既定でオフ(`logUnboundAddresses`)。型・Record の不一致と読めないデータは `logMismatches`(旧 `logUnhandled`)で既定で毎回出す。(D-102)
- **レコードと一覧の受け口**: レコードの行は `OscRecord` 1 個で `UnityEvent` に渡す(名前空間 `OscDesk.Receiver`)。UI で管理する一覧は Strings の行(`string[]`)で受け、その行は `[s:ID, s:Name, ...]`(Record Row Ids)。(D-063・D-075・D-087)
- **受け口の補助部品**: 受信の観測と途絶・再開のイベント(D-060)、トリガ待ちのアプリ向けの再送の窓 `OscResendWindow`(D-097)、レコードの帳簿 `OscKeyedBook<T>` / `OscUiRowBook<T>`(D-099)、`[OscAddress]` の宣言からのエディタでの配線(D-100)。どれも受け口の「受けてエコーする」振る舞いは変えない。(D-060・D-097・D-099・D-100)

## UI との契約・プロトコル

- **フレームの形**: WebSocket のフレームは `v` と `type` を持つエンベロープ付きの JSON オブジェクト。不正なフレームはそのフレームだけを捨てて記録し、接続は保つ。型タグ付きの OSC の引数(blob は base64)は `osc.*` のフレームにだけ残る。(D-028・D-110)
- **設定の配布**: 設定は `unity` / `bridge` のブロック(と SPA の `webUi`)で、起動時に解決した値をブリッジの READY 行と `hello` で配る。UI は設定ファイルを読まない。撤去した NiceGUI 版の `ui` ブロックと `--ui-port` は、警告を出して読み捨てる(フォークの古い設定でも起動は止めない)。ネットワークの 3 つの設定だけは実行中に変えられる(下の「送り先とネットワーク」)。(D-029・D-113・D-138・D-162)
- **パラメータ ID の語彙**: 値の操作は `set {param, value}`、行は `setRow`、まとめ送りは `batch`、保持値は `desired`、エコーは `echo`、一覧は `runtimeOptions*`(一覧の id で指す)、設計図は `catalog`。どれも定義の版(`revision`)が採用中と違えば断る。(D-110・D-117)
- **部品の木**: ブリッジが採用のときに表示する部品の木を組んで `surface.view` で配る。部品は `view.controls` に 1 件ずつ持って添字で指し、木は 8 MiB まで。上限を超えるアクションは `truncated: true`。空の `columns` は全フィールド。(D-124・D-125・D-128)
- **編集は命令で**: 定義(`surfaceEdit` → `surfaceEdited`)とパッド(`osc.padEdit` → `osc.padEdited`)の編集は、作業コピーと命令 1 つを送り、ブリッジが規則を当てた結果を要求元へ返す。ブリッジは作業コピーを預からない。答えを待つ命令は 1 つで、パッドの入力欄の命令だけは欄ごとに最後の 1 つを預かる。(D-123・D-126)
- **操作中のロック**: 部品と Record の行を単位にした 2 秒の期限つきの貸し出しで、持ち主は接続とページ(`holder`)の組。ほかの持ち主のロック中の単位を含むまとめ送りはまとめごと断る。(D-111)

## サーフェス定義と値

- **定義の形式**: 操作対象は OscDesk 側のサーフェス定義(パラメータ層 + 画面層)。版 2 で、本体(id・型・制約・表示ヒント・アクション・画面)と OSC の結び付け `bindings.osc`(ID → アドレス、一覧、アクションのセレクタ)に分ける。zod(`packages/shared/src/surface-definition.ts`)が正典で JSON Schema を生成し、判定は TS だけが行う。UI へは `surface` で本体と結び付けを別の欄で配り、保存は `surfaceSave` 1 回で両方を送る。ブリッジの中はアドレスの形のまま動き、採用時に `resolveOscSurface` で解決してフレームの出入りで変換する。版 1 は読み込み時に版 2 へ移し、保管フォルダのファイルは `.backups/` に退避してから版 2 で書き直す。(D-043・D-117・D-122)
- **型・制約・表示ヒント**: 型は `i` / `f` / `s` / `bool` と値を持たない `trigger`(kind)、Record。Range は型でなく制約。表示ヒント `widget` は画面層 → パラメータ → 型と制約の規則の順で決まる。拡張パッケージは基本型・Record・配列の組み合わせで型を定義して設計図に載せ、フラットな Record を `type: "composite"` として 1 アドレスへ引数の並びで送る(値は JSON のオブジェクト。入れ子・可変長は CBOR の Blob に先送り)。知っている表示ヒント(今は `color`)なら専用の部品、知らなければフィールドごとの部品を組む(部品の木はブリッジが組む)。(D-103・D-121・D-124)
- **保管と配信**: ブリッジが `surfaces.dir` に名前付きで保管し(上書きのたびに `.backups/` へ 20 件)、`surface` 系のフレームと同じポートの HTTP で扱う。CORS は付けない。(D-044)
- **保持値と再送**: `state` の狙いの値はブリッジが持ち、初回の到達・喪失からの回復・定義の採用で再送する。`trigger` と `standalone: false` は保持も再送もしない。エコーは届いた確認で、食い違っても保持値を書き換えない(警告だけ)。ping 間隔より速い Unity の再起動は検知できず、UI の「再送」で補う。(D-045・D-051)
- **保持値の保存**: 定義名ごとのファイル(`surfaces.valuesDir`)へ 500 ms 間引いて原子的に保存し、ブリッジ起動後の最初の採用(と、未送信の印のある定義の採用)で、id・アドレス・型・値域が合うものだけ戻す。形式はレコードの行・UI で管理する一覧・未送信の印を足して版を上げてきた(前の版の生成の記録は読み捨てる)。(D-058・D-062・D-087・D-090)
- **複数のターゲット**: 主系 + 副系を持ち、操作は全宛先へ送る。再送は宛先ごとに行え、「再送」タブから 1 台ずつか全台へ。値の表示に使うエコーは主系だけ。(D-046・D-094)
- **まとめ送り**: 定義の `actions`(パラメータか selector の steps、レコードの `scope: "row" | "all"`)を UI が展開し、上り `batch` 1 個をブリッジが 1 つの OSC bundle(512 件 / 60 KiB まで)にして送る。完了はエコーで確かめ、再送しない。拒否(`batch-rejected`)は `batch` の省略可の `requestId` で要求元のまとめに結び付ける。アクションのボタンには定義のラベルだけを出す。(D-050・D-061・D-069・D-117・D-141)
- **実行時の一覧**: Unity が実行時に持つ文字列の一覧は、定義が宣言したアドレスへ届く値として宛先ごとに持ち、全台の和集合を選択肢にする(順序はブリッジが組んで `runtimeOptions` で全量を配る)。一覧から消えた保持値も残す。届いた一覧は宛先の初報だけを自動で反映し、その後の変化は UI の「反映」で取り込む。要求を持つ一覧の近くに Sync を置き、その一覧の要求だけを送れる。(D-053・D-054・D-055・D-056・D-088・D-077)
- **レコード**: 個数が実行時に変わる対象は、先頭がキー(`s`)でフィールドが続く 1 アドレスのレコードで表し、キーの一覧は `keysFrom` で受ける。保持値はキーごとの行で、新しいキーの行は一覧を反映したときにブリッジが `default` で作って送る。一覧から消えたキーの行は残る。`keysFrom.source: "ui"` の一覧は UI から行を足し・消し、行は変わらない ID で指して Name を別に持つ。(D-059・D-061・D-062・D-075・D-087)
- **設計図からの既定の画面**: ブリッジが設計図から既定の画面を作り(1 項目 1 パラメータ)、`blueprint-<PC 名>-<CRC32>` の名前で保存した画面を優先する。設計図そのものはブリッジの再起動をまたいで保存しない。照合が合わない PC は送り先ブロックの赤い枠と印で示し、到達の点灯には混ぜない。(D-112・D-118)
- **プロジェクトファイル**: 定義・保持値・OSC パッドを 1 ファイル(版 2、12 MiB まで)にまとめ、ブラウザでダウンロード・アップロードする。読み込む前に `projectInspect` でブリッジに判定させ、取り込みは画面と保持値の置き換えだけで、全宛先への「Unity へ送る」まで自動の再送・一覧の要求も止める(印は保持値のファイルに残す)。パッドは版 1 の形で載るので、版 1 で表せない部品を持つパッドの採用中は書き出しを断る。パッドの保持値は載らない(版 3 への切り替えは HID-491)。前の版のファイルの生成の記録は読み捨てる。(D-090・D-117・D-122)
- **SPA のプロジェクトファイル**: SPA の書き出しは `project` をその場で Blob にしてブラウザに保存させ、読み込みは File API で読んだファイルを UTF-8 の JSON のオブジェクトとして読めるか(Infinity になる数を断る)だけを見て `projectInspect` に渡す。答えは印と 15 秒の期限だけで待ち、溜めない。(D-150)
- **SPA の編集モード**: 編集モードはページ全体で 1 つ(`edit-mode.ts`)で、画面の上部のスイッチで入り切りする(ブリッジには送らない)。入り切りは定義の編集の store に任せ、未保存の変更があれば破棄の確認の間はオンのまま。プロジェクトの読み込みはその間だけ出す。(D-151・D-156)
- **SPA の設計図のタブ**: 組み合わせの型を画面に出せるかの目安は shared の `parseCompositeType`・`flatCompositeFields` で見て、`catalog-adopt-rejected` の理由を通知に出す。「新しい一覧があります」も同じ形で移す。(D-152)
- **OSC パッド**: 収録回ごとの撃ち物は、サーフェス定義と別の文書としてブリッジが名前付きで保管・採用し、全端末で共通。押下はボタンの id と版の印で送り、ブリッジが 1 メッセージにする。保持値・再送には載せない。実行モードは `pointerdown` で送る。(D-080・D-081)
- **パッドの文書の版 2(HID-483 で移行中)**: 作り直しの後の画面の文書は `oscdesk-pad` の版 2(`packages/shared/src/pad-document.ts`)。格子に部品(`widgets`)を置き、種類はボタン・トグル・スライダー・選択・数値と文字の入力・色・組み合わせ・表。値を持つ部品と表の欄は「送り直す」(`resend`、省略はオン)を持ち、`readOnly` は表示だけ。表は行の根のアドレスの下に、ターゲットが持つ行か UI で管理する行(ASCII のキーと表示名)を持ち、欄ごとのアドレスで送る。bool は部品のアドレスの型に従い、`T` なら T / F、`i` なら 0 / 1 で送る。OSCQuery のノードから部品を決める規則(`padWidgetFromNode`)・版 1 からの移行・編集の規則(`applyPadDocumentEdit`)・プロジェクトファイルの版 3 のスキーマは shared とブリッジの domain にある。ブリッジの保管とフレームは版 2 に移った(下の「パッドの保持値と同期」)。SPA の主画面はこの版 2 を描く(下の「SPA の主画面のパッド」)。(D-167)
- **パッドの保持値と同期(HID-483 で移行中)**: パッドは版 2 で保管し、採用のたびに `osc.padDocument`(版 2)と、版 1 で表せるボタンだけの `osc.pad`(旧い画面用。HID-491 で撤去)を配る。版 1 で表せない部品を持つパッドへの版 1 の上書きは断る。保持値は値を持つ部品ごと(表は行と欄ごと)の JSON の値で、`osc.padSet`・`osc.padSetCell` で送れたものだけを持ち、`osc.padValues` で配り、パッドの名前ごとの `<名前>.pad-values.json` に残して採用のたびに今のパッドで成り立つものだけ戻す。同じアドレスの値の部品は先に置いた部品が値を持つ。自動の再送(`osc.padResendSet`。既定は切)は、`/sys/pong` の第 2 引数と `HOST_INFO` の起動 ID が前に見たもの(ブリッジの再起動をまたいで残す)から変わったときだけ、その 1 台へ送り直す。手動の同期(`osc.padSync`)は今の宛先・答えた PC・OSCQuery で見つけたターゲットへ。どちらも「送り直す」の部品だけを `/sys/sync/begin ,s boot|manual` と `/sys/sync/end` で挟んで送る。エコーは部品の語彙で `osc.padEcho` に載せ、食い違いは警告だけ。生成の記録は撤去した。(D-169)

## UI の画面

- **画面の組み立て**: UI はブリッジが配る部品の木を描き、画面層は行・列・グループ・タブ・12 分割の幅(狭い画面では折り返す)で並べる。画面が複数なら最上位のタブで切り替える。同じ内容の再配信では作り直さない。(D-047・D-048・D-124)
- **入力欄の保護**: 入力欄のホールドはフォーカスで始め、フォーカス中は延長する。未編集のままフォーカスを外しても送らない。(D-033)
- **定義の編集モード**: 明示のスイッチで入る作業コピー方式。採用中の定義が変われば、未編集なら追従し、編集中なら保って警告し、保存時に上書きを確認する。一覧は 200 行ずつ描く。(D-049・D-123・D-125)
- **SPA の定義の編集**: 作業コピーと答えを待つ命令 1 つだけを持つ(規則はブリッジ)。振る舞い(待つ間は次の命令・保存・追従をしない、15 秒・切断・閉じたら待つのをやめる、競合の警告と上書きの確認)で動く。独自の切り替えは持たず、編集モードの間だけ主画面のタブに出す。(D-144・D-156)
- **一覧の候補と反映待ち**: `optionsFrom` の欄は `runtimeOptions` の候補で select を差し替え、画面は作り直さない。一覧に無い現在値は印を付けて残す。反映待ちの一覧は「新しい一覧があります」に出す。(D-056・D-088)
- **レコード表**: 行 = キーの表で、行の表示キャッシュは行単位。行の増減で作り直さない。欄はカードで包まない低い 1 段。列の一括操作(ボタン・一括トグル)は見出しの直下、表全体のアクションは表の右の縦長ボタン。一括トグルは全行オンのときだけオンで、混在はオフ +「一部オン」。(D-064・D-066・D-072・D-073・D-074・D-076・D-094)
- **右側の領域**: 画面の右側(置き場が 960px 未満では本体の上)に送信先パネルを常に出し、OSC パッドのボタンを選んだ間だけ同じ領域を Inspector に貸す。幅はつまみで変えられ、ブラウザごとに覚える。(D-086・D-089・D-091)
- **OSC パッドの編集**: 格子の大きさは Inspector の外で、実行モードでの変更は表示だけ(保存しない)。ボタンの設定のコピーは既存のボタンへの貼り付けだけに使う。編集モードの案内は格子の上。(D-084・D-089・D-091)
- **ログと通知**: ヘッダーの「ログ」で開くドロワーに、送信ログ(ブリッジの記録)と通知の履歴(ページごと 200 件)を切り替えで出す。(D-067)
- **SPA の主画面**: ブリッジが配る部品の木を描くだけで、値の手触り(操作中の保護・30 Hz の間引きと最後の値・期限・保持値の全量での置き換え)を TS に持つ。部品は 1 つの値の出し入れを受けて描き、通常の部品・組み合わせの型・レコードの欄で共用する。画面は定義の内容が変わったときだけ作り直し、切断中は部品を無効にする。ロックの印はタブごとに 1 つで、名前はブラウザと端末の種類から作り、期限で切れた操作のロックは外す。選択は押してから選ぶまで、色は決めたときだけを送る。(D-141・D-142・D-143)
- **SPA の OSC パッド**: Inspector は広い画面ではパッドのタブを見ている間だけ右の列(送信先の場所。送信先パネルは隠すだけ)に、狭い画面では格子の下に出す。保存・切り替えの応答の照合と追従は `osc.pad` が届いた時点で行い、答えを待つ間に届いた採用だけを答えの後に照合する(採用の履歴は持たない)。答えを待つ間・画像の読み込み中は入力欄の命令だけを預かり、ほかの操作(選択・コピー・貼り付け・構造の命令・画像・新規・保存・切り替え・実行モード)は理由を出して断る。画像の読み込みは始めたときの作業コピーの世代を持ち、替わっていれば捨てる。Inspector の入力欄は打った文字を欄に残し、断られた理由を欄の下に出す。(D-147・D-155・D-160)
- **SPA の主画面のパッド**: 主画面はパッドの版 2 で、最初に開くタブ。部品は格子のマスに広がりの分だけ置き、ボタンは `osc.padPress`、値の部品は `osc.padSet`、表のマスは `osc.padSetCell`、表のアクションは `osc.padAction` で、描いているパッドの名前と `version` を付けて送る。`version` の違う値・エコーは当てず、同じ内容の再採用では作り直さず、内容が変わったら送信待ちを捨ててロックを外す。値の手触り(操作中の保護・30 Hz の間引きと最後の値・期限・下書き)は主画面と共用の `value-channel.ts`。ロックは値の部品が `{widget}`、表は行。同じアドレスの持ち主の規則は写さず、断られたら保持値を取り直す。表の行は UI で管理する行なら文書、ターゲットが持つ行なら保持値と OSCQuery の名前空間の和で、一括トグルは行ごとに送り、UI で管理する行の変更は採用中のパッドを編集して保存する(待つ間にパッドが替わったら保存しない)。編集は版 1 の OSC パッドの編集と同じ規則(`osc.padDocumentEdit`)で、空きマスに部品を足すか、OSCQuery のパレットの候補を置く(`addWidgetFromNode`。候補は 1 ターゲット 200 件まで描き、未対応も理由つきで出し、「再読み込み」は `osc.queryRefresh`)。「同期」タブに自動の再送の入り切りと、手動の同期の行き先(全宛先・宛先ごと・OSCQuery のターゲットごと)。(D-170)
- **SPA の通知の履歴とドロワー**: 通知の履歴は共有の `notices.ts` の `notify` が残す(タブごと 200 件)ので、どのパネルの通知も手を入れずに履歴に載る。右上の「ログ」で開くドロワーに送信ログと通知の履歴を 50 行ずつ出す。(D-148)
- **SPA の画面の枠**: 上に接続の状態、その下にタブ(パッド・同期・送信先・ネットワーク)。サーフェスの主画面・編集モード・設計図・版 1 の OSC パッド・再送のタブは外した(コードの撤去は HID-491。それまで外した画面の DOM のテストは外す前の枠の写し `legacy-app.tsx` で走る)。送信先は幅 960px 以上では右の列に出し続け、狭い画面ではタブにする。タブの中身は切り替えても消さずに隠す。store は `stores.ts` で 1 回だけ作る。通知の枠の高さだけページの下に余白を足し、アイコンは `index.html` に埋め込む。(D-156・D-170)
- **SPA の右の列の幅**: 広い画面では本体と右の列の間のつまみ(タッチ・矢印キーでも動く)で幅を変え、離したときに `localStorage` の `oscdesk.asideWidth` に覚える。下限 260px、上限は本体に 360px とつまみを残す幅で、CSS の clamp() でも常に抑える。右の列はタブの帯の下に貼り付けて自分でスクロールする。(D-159)
- **SPA のダイアログと Inspector の打った文字**: ダイアログ(`.backdrop`)はどれも `Modal` で包み、画面の枠の直下の置き場(`.modal-root`)に描く(右の列などの重なりの文脈の外。preact/compat は使わない)。OSC パッドの Inspector の欄に打った文字は store にも持ち、タブの切り替えや置き場所の移動で作り直しても、断られた文字と理由を並べて出す。(D-161)
- **SPA の初期の要求と「パッドが無い」**: 接続ごとの初期の要求(OSC のアダプタがあるときの `osc.padDocumentRequest` だけ。`surfaceRequest`・`osc.padRequest` は送らない)は `bridge-link` が `hello` の後に 1 回だけ送り、各 store は答えを受けるだけ。パッドの一覧の `active` が null なら、パッドの画面は待たずにパッドが無いことと作り方を案内する。(D-155・D-170)
- **SPA の一覧の反映と通知の受け持ち**: 主画面の「一覧を更新」・Sync で届いた反映待ちは、主画面のタブの「新しい一覧があります」に出して `runtimeOptionsApply` で反映する(ほかのタブではタブに印)。notice の code ごとに通知する store は 1 つだけ。(D-157)
- **SPA の Unity の接続状態**: ヘッダーに Unity の到達・RTT・連続喪失(link の表示キャッシュ。ブリッジとの接続が切れたら「未確認」に戻す)。`resend-rejected` の通知はこの store だけが出す。「再送」タブは外し、パッドの「同期」タブに置き換えた。(D-158・D-170)

## 送り先とネットワーク

- **送り先の選択と走査**: 送り先は送信先パネルで実行中に選び直せ、走査・検証・保存はブリッジ(選択は `<保持値の保存先>/.destinations.json` に保存し、設定ファイルの宛先より優先)。LAN の走査は UDP の掃引 + ARP 表で、/24 まで。選べるのは設定の宛先と、この PC のネットワークの中のユニキャストアドレスだけ。(D-078)
- **ブロードキャスト**: 「全てのデバイス」とネットワークごとの全てのデバイスはブロードキャストアドレスへ送り、pong を返したホストごとに到達を数え、新しく答えたホストへだけユニキャストで再送する。届くかの判定は、ホストを含む最も狭いネットワークで行う。親を選ぶと子にもチェックが付き、子を外すと親を外して残りを個別の選択へ展開する。(D-079・D-085・D-089・D-093)
- **SPA の宛先パネルの手触り**: 押したチェックは応答を待たずに手元で先に付け、断られた・3 秒で反映されない・切断のどれかで取り消す。検索の正規表現の照合はそのタブの中で走るので時間の上限を置かない。(D-140・D-162)
- **端末の名前**: ブリッジが走査の後に DNS の逆引きと OS の名前解決で引く。UI から別名を付けられ、ブリッジが MAC(分からなければ host)をキーに `.device-aliases.json` へ保存する。表示は 別名 → 引けた名前 → IP。検索は正規表現(読めない式と時間のかかる式は文字どおりの部分一致)で、一致しない端末と、一致する端末の無いネットワークを隠す(選択は残す)。検索中の「全て」は表示中の端末だけを個別の選択として付け外しする(ブロードキャストにしない)。(D-085・D-086・D-089・D-092)
- **送り先ブロックの点灯**: 送ったものへの返事(届いた・対象なし・処理失敗)をブリッジが通信アダプタの受信と突き合わせて `delivery` で配り、送り先ブロックを緑・黄・赤で光らせて 10 秒で退色させる。(D-116)
- **実行中に変えられるネットワークの設定**: ターゲット向けのネットワーク・ターゲットがいる範囲(CIDR)・接続してよいブラウザの範囲(CIDR の許可リスト)を、どのブラウザからでも変えられる(`.network-settings.json` に保存。設定ファイルへは書き戻さない)。ブラウザ向けは常にすべてのネットワークで待ち受ける。許可リストは UI の HTTP とブリッジの両方で判定し、localhost は常に許可、操作元を締め出す変更は断る。(D-113。覆した: D-029 の「起動時に確定」のうちこの 3 つ)
- **ブラウザからの接続の判定**: ブリッジの HTTP 全体と WebSocket は、Host が IP アドレスの直書きかこの PC の名前でなければ断る(DNS の再束縛への備え)。`Origin` 付きの WebSocket のハンドシェイクと状態を変える HTTP は、ブリッジ自身が配ったページ(Origin の host:port が Host と同じ)のものだけを受け、第三者のページと `Sec-Fetch-Site: cross-site` の状態を変える要求は断る。Origin の無い接続(mock・テスト・curl などブラウザでない道具)はそのまま受ける。HTTP の 403 は日本語の案内を返す。(D-082・D-083・D-138)
- **SPA のブラウザの許可はブリッジだけ**: SPA のブラウザはブリッジへ直接つなぐので、ページの HTTP と WebSocket の許可も、操作元を締め出す変更の拒否も、ブリッジが接続の送信元で判定する。`networkSettingsSet` に操作元を名乗る項目は無く(NiceGUI 版の中継のための `browser` は消した)、SPA は範囲の外の予告もしない(判定の写しを持たない。断られた理由を通知に出し、入力は残す)。(D-153・D-162)
- **`hello` の送信元**: `hello.peer` はブリッジから見たその接続の送信元で、SPA の「このブラウザ」の表示と「このブラウザを足す」にだけ使う。判定には使わない。(D-154)
- **OSCQuery での発見と部品の候補**: ブリッジはターゲット向けのネットワークの IPv4 の NIC ごとに `multicast-dns` で `_oscjson._tcp` を探し(設定の `oscQuery.targets` で直接指定もできる)、`HOST_INFO` と名前空間を自前の HTTP で読む(204・400 は未対応、8 MiB・深さ 32・ノード 20,000・5 秒の上限、名前空間は保管しない)。送り先は HTTP を取ったアドレスの `OSC_PORT`、起動 ID は `X_OSCDESK_BOOT_ID` と pong の第 2 引数。書けるノードを部品の種類つきで `osc.queryTargets` に配り(種類は編集の `addWidgetFromNode` と同じ `padWidgetFromNode` で決め、作れないノードは未対応にする。D-171)、`PATH_*` を受けたら間引いて読み直す。見つけたターゲットは宛先パネルの端末の `services` に並び、ホストと `OSC_PORT` の組(`endpoints`)で選んで保存する(同じ PC の複数のアプリを区別し、発見が消えても送り先を変えない)。E2E の mDNS は帯のポートとループバックだけで流す。(D-168・D-171)

## 永続化と診断

- **証跡**: 証跡は debug 起動時の NDJSON(`logs/diagnostics/oscdesk-*.ndjson`)とブリッジの標準出力に集約する。画面上の診断パネルと手動のログ削除は持たず、容量上限は debug 時も自動パージで守る。(D-031)
- **送信ログ**: Unity へ送った OSC はブリッジが直近 1,000 件をメモリに持ち、`osc.sentLog` で配る(250 ms ごとにまとめる。揮発する表示用で、証跡ではない)。(D-067・D-110)
- **想定外の例外**: 上りのフレーム・OSC の受信・HTTP の処理で起きた想定外の例外は、その 1 件だけを捨てて `(ERROR, BRIDGE)` に記録し、ブリッジを止めない(要求元がいれば `internal-error` か 500 で答える)。(D-129)
- **ブリッジが持つファイル**: 定義(`surfaces/*.json` と `.backups/`)、保持値(`surfaces/.values/<名前>.values.json`)、パッド(`surfaces/pads/` と `.active.json`)、送り先の選択・端末の別名・ネットワークの設定(保持値の保存先の `.destinations.json`・`.device-aliases.json`・`.network-settings.json`)。どれも一時ファイル + rename で原子的に書き、読めないときは警告して既定で起動する。(D-044・D-058・D-080・D-078・D-092・D-113)

## テストと開発

- **パッケージ管理**: pnpm は corepack 経由(`packageManager` で固定)。(D-004)
- **Unity の受け口は別リポジトリ**: 受け口のパッケージと検証用の Unity プロジェクト、Unity CI、パッケージの検査(旧 `tests/guards/unity-package.test.ts`)は `Hidano-Dev/oscdesk-unity` にあり、`corepack pnpm test` の対象外。本リポジトリの `checks.unity_ci` は null。(D-136。覆した: D-005)
- **OSC のコーデック**: `osc` npm は `osc-codec` に閉じ込め、`shared` はライブラリ非依存の wire 型だけを持つ。(D-006)
- **E2E の方針**: E2E は実プロセス(bridge・mock-unity)を起動し、WebSocket と OSC のクライアントで検証する(実ブラウザの描画は手動の目視で確かめる)。全断は mock-unity の silent フォールトで再現する。E2E のファイルは並列のワーカーで動かし、ポートはワーカーごとに重ならない帯から、ブリッジの保管先は起動ごとの一時フォルダから取る(既定のポートを使うと落とす)。(D-032・D-013・D-133)
- **SPA の画面のテスト**: SPA の画面のテストは `*.test.tsx` に書き、vitest の unit の中で happy-dom の DOM に描いて、偽の WebSocket で送ったフレームと DOM を確かめる。実ブラウザ(Playwright の開発用 Chromium)は手動検証と計測にだけ使う。(D-139)
- **フォークのオーバーレイ**: フォークの固有のファイルは直下のディレクトリ 1 つに集め、`oscdesk.overlays.json` に書いたものだけをテストの入口に足す。追跡中のテストがどこかの実行に入ることは `tests/guards/test-roots.test.ts` が守る。テストは vitest だけで、オーバーレイの `tests/` に Python のテスト(`test_*.py`・`*_test.py`)が残っていれば同じガードが落として書き直しを案内する。画面のテストは `packages/web-ui/src/overlay-test-support.ts` の `mountSpa` で SPA を描いて書く。(D-132・D-162)
- **手動検証の準備**: 手動検証の定義・一時の config・mock-unity は検証用ランチャー(`launchers/start-oscdesk-verify.ps1`)が用意し、ランチャーはブリッジの出力を起動ウィンドウへ中継する。(D-065)

## ランチャー

- **プロセスの後始末**: ランチャーは子プロセスを Job Object で親と道連れにし、起動時に親の消えた孤立プロセスを回収する。回収するのは自分のチェックアウト(`<root>\packages\` の下)から起動したものだけ(撤去前に起動した NiceGUI 版の残りも拾う)。子の標準出力・標準エラーは `logs/launcher/` に置き、持ち主のランチャーが消えたものを起動時に片付ける。(D-039・D-068・D-135)
- **置き場所と自動 setup**: 直下には `start-oscdesk.bat` だけを置き、用途別ランチャー・setup は `launchers/`、共通部品は `launchers/lib/`。ランチャーは起動前にファイルだけで依存・ビルド成果物(ブリッジ・mock-unity・SPA)を確かめ、足りなければ setup を自動で実行する(`-CheckOnly` で確認だけ)。通常起動はブリッジだけを起動し、SPA の URL を出す。`.bat` は ASCII だけ、`.ps1` は UTF-8 BOM 付き(`tests/guards/launcher-scripts.test.ts`)。(D-068・D-162)
