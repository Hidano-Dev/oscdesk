- [x] 1.1 マニフェストと stats のスキーマに、起動の識別子と構造の世代を任意項目として足す

  - 起動の識別子は 1〜64 文字、構造の世代は 0〜2,147,483,647 の整数に縛る。未知キーを取り除く既存の挙動は変えない
  - 組を表すスキーマと型を export し、ブリッジと mock-unity から使えるようにする
  - wire サンプルに、組を持つマニフェストのフレームを足す(組を持たない既存のサンプルは残す)

- [x] 1.2 マニフェストの採否に、同じ組の重複判定と到達性回復後の強制採用を足す
  - design の採否の表の順(強制採用 → 未受理 → 組なし → 同じ組 → それ以外)で判定し、同じ組のときだけ「重複」を返す。大小は比べない
  - 採用時に受理済みの組を更新し、目標の組と一致するか目標が無ければ settled、違えば requesting のまま要求を続ける
  - 到達性の回復で requesting にし、次の受信を組に関係なく採用する旗を立てる
  - 起動の識別子が直前の受理と変わった採用を、結果で区別できるようにする
  - `expectedProjectId` の照合、JSON・スキーマの拒否は従来のまま保つ
  - 完了時: 同じ組の再受信で重複が返り、違う組(世代が小さくても)と回復直後の同じ組は採用される単体テストが緑。組を持たない送信元は受信ごとに採用される
  - _Requirements: 8.1, 8.2, 8.3, 8.7, 8.8, 8.9_

- [x] 1.3 stats による定期照合の状態を足す
  - 組を持つマニフェストを受理済みの間だけ、4 秒間隔(注入可能)で stats の要求が必要だと判定する
  - stats の受信を、不正・対象外・一致・不一致に分類する。不一致なら目標の組を記録して requesting にし、直前の要求時刻を消してすぐ要求できるようにする
  - 一致なら目標を消し、強制採用の旗が無ければ settled にする。不正な stats は同じ理由の連続を抑制できるようにする
  - 完了時: 不一致 → 即時の要求 → 目標の組を受理するまで要求が続く、途中で届いた別の組も採用される、組なしの受理済みでは stats を要求しない、の各単体テストが緑
  - _Requirements: 8.4, 8.5, 8.6, 8.8_

- [x] 1.4 ブリッジの配線で、重複では採用を発行せず、stats の照合を送受信する

  - Unity ホストからの stats を照合に渡し、UI へは配信しない。Unity 以外の送信元からの stats は捨てる。不一致は INFO で 1 行出してすぐマニフェストを要求する
  - 重複の受信では adoption の番号を進めず、マニフェストもリンク状態も配信しない。起動の識別子の変化は INFO で Unity の再起動として 1 行出す
  - 「stats を黙って捨てる」既存テストを、「UI へは配信しない」「Unity 以外からは照合に使わない」に書き換える
  - 時計と受信の注入で、再注入のマニフェスト 1 通の喪失からの回復と、到達不能を経ない Unity の再起動を決定的に再現するテストを書く
  - `docs/BRIDGE_PROTOCOL.md` に、マニフェストの新しい項目、採用を発行しない条件、再起動の検出、照合の送信で Unity の受信数が増えることを記す
  - 完了時: 組を持たないマニフェストで既存のブリッジのテストが全件緑のまま、喪失と再起動の各順序のテストが緑
  - _Requirements: 8.2, 8.4, 8.5, 8.6, 8.7, 8.10, 10.5, 11.5_
