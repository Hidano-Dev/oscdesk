# 実装計画

## 前提条件(着手前に必ず確認する)

- **着手条件**: 本 spec の実装着手は先行 spec `manifest-input-select-widgets` の実装完了後とする。`OscSurfaceManifestAsset.cs` / `OscSurfaceBridge.cs` / `docs/UNITY_PROTOCOL.md` 付録 A.2 / mock-unity を双方が変更するため、並行すると確実に衝突する
- **テスト入口**: 自動テストは `corepack pnpm test`(vitest + pytest)のみ。Unity EditMode テストは `pnpm test` からも CI からも実行されないため、実行方法の文書化(`docs/VERIFICATION.md`)を完了条件に含める
- **Unity アセット追加時の規律**: `OscSurface/Assets` 配下へ追加する全ファイル・全フォルダに `.meta` を用意し、GUID は都度ランダムな 32 桁 hex を生成する(`[guid]::NewGuid().ToString('N')`)。既存 `.meta` からのコピー、連続パターン、ローテーション系列は禁止
- **境界規律**: `packages/shared` / `packages/bridge` / `packages/nicegui-ui` は変更しない。実装中に境界を越える必要が判明したら独断で実装せず、差分と選択肢を添えてユーザー判断へ返す
- **本 spec の完了条件(全タスク共通)**: `docs/UNITY_PROTOCOL.md` 付録 A.2 の構成更新と全文同期、互換性ノート 3 件の記録、`docs/VERIFICATION.md` への手動検証手順追記が済んでいること

- [x] 5.3 受信処理を中核へ委譲し、エコー順序・展開エコー・適用イベント発火を実装する
  - 通常メッセージ受信の順序を「記録可能引数の抽出 → 中核へ委譲 → 受信アドレスへ受信引数そのままのエコー → 展開先へ単一引数の個別エコー → 適用成立時にイベント発火」に固定する。エコーは必ずイベント発火より先に完了させる
  - 適用イベントを C# の `event` として公開し、トリガアドレスと適用範囲の順序付き値辞書を引数で渡す。インスペクタ結線は提供しない。購読者は 1 件ずつ例外隔離して呼び、例外はログに記録して次の購読者へ進む
  - ステージング対象と非対象で、応答アドレス・型タグ・追加メッセージ・遅延に区別できる差分を作らない。新しいアドレス・型タグ・メッセージ種別は追加しない
  - 中核の値型と OSC の値表現の変換は private ヘルパ 1 組に閉じる。既存の正規化はエコー経路で維持する
  - 同一ファイルを 5.2 / 5.4 も変更するため、5.2 → 5.3 → 5.4 の順に実施し並行実行しない
  - 完了条件: 編集値の受信ではエコーのみで適用が起きず、トリガの非ゼロ値受信でエコー後に 1 回だけイベントが発火し、値 0 の受信ではエコーのみになる。展開元受信では展開元と展開先の双方へエコーが出る
  - _Requirements: 2.2, 2.3, 2.5, 3.1, 3.1a, 3.1c, 3.2, 3.3, 3.6, 4.2, 4.4, 6.4_
