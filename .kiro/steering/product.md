# プロダクト概要

OSCDesk は、Unity アプリ(将来的には任意の OSC 受信アプリ)を LAN 内のブラウザやスマートフォンから操作するための、双方向 OSC コントロールサーフェスである。Node.js のブリッジが Unity との OSC/UDP 通信と UI との WebSocket 通信を仲介し、NiceGUI(Python)の UI が表示と操作を担当する。

想定利用者は、舞台・配信・展示などで Unity 側のパラメータを手元の端末から操作するオペレータと、その現場を構築する開発者である。

## コア機能

- **マニフェスト駆動の UI 生成** — Unity が `/sys/manifest` で「操作できる対象」(アドレス・ラベル・型・ウィジェット種別・レンジ・グループ)を宣言し、UI はそれを受けて画面を組み立てる。UI 側に案件固有の画面コードを持たない
- **双方向の OSC 中継** — ブリッジが OSC/UDP とエンベロープ付き JSON の WebSocket フレームを相互変換する。UI の操作は Unity へ、Unity のエコーバックは全 UI クライアントへ流れる
- **死活監視と診断** — `/sys/ping` / `/sys/pong` による RTT・連続喪失の観測、接続状態の UI 表示、NDJSON による送受信証跡の記録(容量上限つき自動パージ)
- **誤接続ガード** — マニフェストの `projectId` が設定の `expectedProjectId` と一致しない場合は採用せず、表示中の値を差し替えない。拒否は専用の NDJSON に記録する
- **Unity 非依存の開発・検証** — mock-unity(OSC レスポンダ)がシナリオ JSON に沿って Unity 役を務めるため、Unity Editor なしで開発とテストが完結する

## 主な利用シナリオ

- **本番運用** — `start-oscdesk.bat` でブリッジと UI を起動し、同一 LAN の端末から `http://<PC の LAN IP>:8080` を開いて Unity を操作する
- **案件の切り替え** — コードではなく、`config/*.config.json` と Unity 側マニフェストの内容を差し替えることで別案件へ対応する
- **開発・自動テスト** — mock-unity + ブリッジ + WebSocket クライアントで、プロトコルと状態遷移を E2E に検証する
- **OSC ネイティブ UI の評価** — TouchOSC など OSC を直接話す UI を `/oscdesk/hello` でエコーバック宛先として登録し、NiceGUI UI と併存させて評価する

## 価値の源泉

- **Unity が真実の源** — UI は表示キャッシュにすぎず、値の確定は Unity からのエコーバックのみで行う。UI 側の楽観更新でズレが固定化しない
- **特定 Unity OSC ライブラリに依存しない** — OSC 1.0 標準の範囲(型タグ `i` / `f` / `s` / `b`)だけでプロトコルを成立させる。ライブラリ固有の事情は `docs/UNITY_PROTOCOL.md` に互換性ノートとして隔離し、Unity 側は独自 Fork でも参照実装を読み替えるだけで接続できる
- **案件差分はコードでなくデータ** — 設定・マニフェスト・mock シナリオで表現するため、案件が増えても分岐が増えない
- **契約が文書化されている** — `docs/BRIDGE_PROTOCOL.md` と `protocol/wire-samples.json` だけで、第三の UI クライアントを実装できる

## 対象範囲と境界

- **開発対象**: ブリッジ、NiceGUI UI、共有プロトコル(型・スキーマ・定数)、OSC コーデック、mock-unity、テストハーネス
- **開発対象外**: Unity アプリ本体。同居する `OscSurface/` は接続確認用の Unity プロジェクトであり、リポジトリが責任を持つのは `/sys/*` プロトコルと参照実装の記述まで
- **セキュリティ前提**: 本システムは認証を提供しない。信頼できる LAN 内での利用が前提であり、インターネットや信頼できないネットワークへ公開してはならない。この前提は README・AGENTS・プロトコル文書・手動検証手順のすべてで繰り返し明示する

## 規律(要件がこれを越える場合は実装前に判断を仰ぐ)

1. ブリッジと UI の責務を分離する。Unity との OSC 通信はブリッジに集約し、UI はブリッジの WebSocket プロトコルだけを使う
2. 案件差分はコードでなくデータ(config / マニフェスト / シナリオ)で表現する
3. Unity が真実の源。UI は表示キャッシュで、値の確定は Unity のエコーバックのみ
